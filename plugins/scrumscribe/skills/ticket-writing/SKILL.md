# Ticket writing

Two passes, in this order:

1. **Precision pass** inspired by ASD-STE100 Simplified Technical English: one meaning per word, short sentences, active voice.
2. **Layout pass** inspired by ADHD-friendly output rules: the point first, numbered steps, short lists, concrete numbers.

This skill summarises principles in its own words. It is not the ASD-STE100 standard and is not certified by ASD. For a full STE rewrite, install a dedicated STE skill (see the README's credits).

## House rules

| Rule | Instead of | Write |
|---|---|---|
| Title = verb + object | Invoice improvements | Export invoices as CSV |
| First line = the user outcome | Refactor the export module | Finance can download a month of invoices in one file |
| One requirement per sentence, about 20 words max | Long sentences joined with "and" | Separate acceptance criteria |
| Active voice | The file is generated by the system | The system generates the file |
| Numbers, not adjectives | The page loads fast | The page loads in under 2 s for 95% of requests |
| One word for one thing | Client, customer and user mixed | The glossary term, every time |
| At most five items per list | Twelve acceptance criteria | Split the story |
| Status at the top | Status buried in comments | `Status: Ready`, `Blocked` or `Needs answer` |
| No hedging | Should probably maybe support | Supports, or an open question |

## Ticket layout

```markdown
Status: Ready | Blocked | Needs answer
Outcome: <one line, user's point of view>

Acceptance criteria
1. Given ..., when ..., then ...
2. ...

Out of scope
- ...

Notes
- Source: <link>
- Open questions: <none | list>
```

## Glossary

If the charter has a `glossary`, use only those terms. If a new term appears, add it to the draft glossary and flag it for the PO.

## Talking to the PO

In chat, use the layout rules only: answer first, number the steps, say which stage you are in, no filler.
